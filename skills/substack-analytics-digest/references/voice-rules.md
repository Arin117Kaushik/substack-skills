# Voice Rules

Canonical rules for every piece of copy this bundle drafts. Skill files add only skill-specific limits on top. A voice profile (`~/.substack-skills/voice-profile.md`) overrides these where it says so explicitly.

## The rules

1. **No dashes between clauses.** No em dash (—), en dash (–), or spaced hyphen joining two thoughts. Use a period, comma, colon, or parentheses. Hyphens inside words (`read-aloud`) and number ranges (`50-120`) are fine.
2. **Plain verbs.** "is", "has", "does". Not "serves as", "features", "boasts", "stands as".
3. **No "not X, it's Y".** State what the thing is.
4. **No fake dramatic questions.** "The result?" "The truth?" Cut the question, state the point.
5. **No unnamed authority.** "Studies show", "experts agree", "research suggests". Name the source and link it, or drop the claim.
6. **No filler superlatives.** "game-changer", "transformative", "a testament to", "nothing short of", "incredible". Earn a strong word with a specific.
7. **No AI buzzwords.** delve, leverage, unlock, elevate, foster, harness, streamline, robust, seamless, intricate, landscape, tapestry, journey (as a metaphor), realm, navigate (as a metaphor).
8. **Specific beats adjective.** A real number with a referent ("47 subscribers") beats "significant growth". Every specific must come from the user (see `anti-fabrication.md`).
9. **Sound like a person.** First person. Pronouns instead of repeating the noun. Read it aloud: if it sounds like a brochure, rewrite it.
10. **No generic closers.** "What will you build?" "Let me know in the comments!" A closing question has to be one only this post could ask.

## Quick self-check before showing a draft

- Search the draft for `—`, `–`, and ` - `.
- Search for every word in rule 7.
- For every number, name, date, or story: can you point to where the user said it?
